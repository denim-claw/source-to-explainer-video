# 한국어 나레이션과 문서 쓰기

나레이션, 자막, README를 한국어로 쓸 때 보는 점검표입니다. 유시민이 『글쓰기 특강』에서
강조한 원칙(주장에는 근거를 붙이고, 짧고 정확하게 쓰고, 소리 내어 읽어 본다)과 박완서의
문장이 보여 주는 태도(쉬운 우리말로, 꾸밈없이, 구체적으로)를 실무 규칙으로 옮겼습니다.
두 사람의 문장을 흉내 내라는 뜻이 아닙니다. 읽는 사람이 한 번에 알아듣게 쓰라는 뜻입니다.

## 다섯 가지 규칙

1. **한 문장에는 한 가지 생각만 담습니다.** 쉼표로 세 가지를 잇고 싶으면 문장을 나눕니다.
   귀로 듣는 나레이션은 더 짧아야 합니다. 40자를 넘으면 한 번 더 봅니다.
2. **주어와 서술어를 맞춥니다.** "이 스킬은 ~를 목표로 하며 ~가 생성됩니다"처럼 주어가
   중간에 바뀌면 고칩니다. "이 스킬은 ~를 만듭니다."
3. **번역투를 걷어 냅니다.**

   | 고치기 전 | 고친 뒤 |
   |---|---|
   | ~를 통해 검증을 수행합니다 | ~로 검증합니다 |
   | ~에 대한 설명을 제공합니다 | ~를 설명합니다 |
   | ~하는 것이 가능합니다 | ~할 수 있습니다 |
   | 결과물을 가지고 있습니다 | 결과물이 있습니다 |
   | 생성되어집니다 | 만들어집니다 / 만듭니다 |
   | 효율적인 방식으로 | 빠르게 (무엇이 얼마나 빠른지 쓰기) |

4. **쉬운 말을 고르고, 이름은 그대로 둡니다.** "산출물" 대신 "결과", "상이한" 대신
   "다른"을 씁니다. 다만 `runId`, `FOR UPDATE SKIP LOCKED`, 파일 경로 같은 코드 이름은
   번역하지 않습니다.
5. **꾸밈말 대신 숫자와 조건을 씁니다.** "대폭 개선" 대신 "1.8초에서 0.4초로". 확인하지
   않은 것은 확인하지 않았다고 씁니다.

## 소리 내어 읽기

- 나레이션은 반드시 소리 내어 읽어 봅니다. 숨이 차거나 같은 조사가 연달아 나오면 고칩니다.
- 영어 약어는 TTS가 읽는 방식을 생각합니다. 커밋 해시는 화면에만 두고 나레이션에서 뺍니다.
- 전환 키워드는 문장 앞쪽에 둡니다. `prepare.py`가 자막 조각에서 키워드를 찾기 때문입니다.

## 영어판과 한국어판

- 영어 문장을 직역하지 않습니다. 같은 주장을 한국어 어순으로 다시 씁니다.
- 수치, 조건, 예외, 고유명사는 두 언어에서 같아야 합니다. 원본 대조 보고서는 같은 장면
  번호로 두 언어를 함께 확인합니다.
